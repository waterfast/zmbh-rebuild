# 重构项目架构总览

更新时间：2026-09-21

本文描述 `refactor/` 当前存在的架构。它保留旧项目可复用的场景布局、碰撞、动画图集和美术资源，再逐步替换运行时职责。`refactor/` 是后续新项目；仓库根目录的旧项目作为迁移和对照来源。

## 1. 重构边界

场景文件应负责节点树、坐标、碰撞体和资源引用；脚本负责规则、状态和生命周期。迁移旧场景时应保留合理的布局和资源，替换耦合旧 Autoload 的脚本，不能只新建同名空场景就称为“已经搬运原 Scene”。

附加的《重构框架建议》和《造梦项目重构规划》是设计参考，不是执行限制或完成证明。本目录文档以当前代码和测试为准，区分框架可用、内容迁移、接入主流程和原版等价验收。

## 2. 目录分层

| 目录 | 职责 |
| --- | --- |
| `Scene/` | 新项目的可编辑场景入口；关卡、主菜单、档位、地图、战斗和主要 UI 均保留原节点和布局 |
| `actors/` | Actor、控制器、运动、玩家输入、敌人 AI 和投射物场景；脚本位于 `Script/actors/` |
| `core/ability/` | 技能定义、来源授予、类别筛选、统一触发请求、消耗、冷却和施法 |
| `core/content/` | 会话级内容注册组合根，以及法宝技能独立注册表 |
| `core/buff/` | Buff 实例、持续时间、周期效果和数值修正 |
| `core/combat/` | Hitbox/Hurtbox、攻击快照、伤害结算、被动 |
| `core/effects/` | 投射物、原动画轨道攻击、近战、治疗、Buff、冲刺效果 |
| `core/state_machine/` | 动作状态与移动状态 |
| `core/stats/` | 基础属性、修正和生命 |
| `content/` | 关卡定义、技能 JSON、装备 JSON 等静态内容 |
| `world/` | 当前关卡加载、释放、门碰撞和 Actor 容器；地图选关脚本位于 `Script/ui/map_screen.gd` |
| `app/` | 应用装配、玩家档案、流程和波次控制 |
| `systems/` | 物品、装备、成长、任务、存档 |
| `presentation/` | ActorView 和迁移后的 SpriteFrames |
| `ui/` | UI 场景和展示资源；脚本位于 `Script/ui/` |
| `Script/tests/` | Godot headless 自动化测试 |
| `addons/godot_ai/` | Godot AI/MCP 编辑器插件及调试辅助 |

依赖由应用层装配：`app` 创建 `world`、`actors` 和 `systems`；Actor 使用核心组件；UI 读取系统数据并发出用户操作。核心战斗层不依赖 UI、旧全局对象或具体关卡节点路径。

## 3. 对象关系与生命周期

```text
GameApp
├── PlayerProfile：跨关卡的背包、装备 UID、成长、任务、保存状态
├── WorldSession：当前关卡的资源寿命边界
│   ├── geometry：迁移后的关卡 Scene
│   └── actors：当前角色、敌人和关卡内飞行物
├── StageEncounter：当前关卡波次和清场规则
└── CanvasLayer：屏幕坐标界面，与世界相机解耦
    └── GameHUD / Inventory / Quest

CombatActor
├── ActorController → ActorCommand
├── CharacterMotor
├── ActionState + LocomotionState
├── Combatant
│   ├── ActorStats + ActorHealth
│   ├── BuffContainer
│   └── PassiveController
├── AbilityController
└── ActorView
```

`CombatActor` 是场景树中的身体节点，`Combatant` 是不依赖场景树的战斗状态。输入、AI、碰撞、数值和表现各有边界，避免角色类知道每个装备和技能的具体名称。

## 4. 控制器与角色状态

输入源输出 `ActorCommand`，控制器将其提交给 Actor。当前有键盘动作源和缓冲输入源；未来手柄或触控可以实现相同接口。Motor 不读取 Input，不知道角色种类，也不处理装备。

状态分成两个对象：

- `LocomotionState`：IDLE、RUN、JUMP、FALL。
- `ActionState`：FREE、ATTACK、SKILL、HURT、DEAD。

这样可以表达“空中攻击”，而不必为移动与动作的每种组合增加新状态。动画消费状态，战斗时序由动作和技能系统决定。

## 5. 定义与实例

装备定义是 `content/items/<id>.json`，515 条原表记录拆为独立文件。`ItemDefinition` 包装静态属性、旧字段和技能引用；`ItemInstance` 仅保存 UID、定义 ID、随机结果、随机来源/等级、强化、五行和宝石。

`ItemCatalog` 使用有界 LRU 缓存。背包实例不持有定义对象，不会间接阻止缓存淘汰。`EquipmentLoadout` 以唯一来源添加属性、技能和被动，卸下时撤销该来源。同一技能有多个来源时，移除一件装备不会删掉角色或另一件装备提供的技能。

技能定义由 `AbilityCatalog` 按路径加载，使用弱引用缓存。`ContentRegistry` 在应用装配时注册运行时技能，`AbilityGrant` 记录定义、来源 ID、来源类别和来源种类；角色技能、装备技能、法宝技能都通过 `SkillTriggerRequest` 进入 `AbilityController.try_trigger()`。效果类承担行为，技能 JSON 或独立注册器提供组合。复杂套装条件和全部旧装备特效仍按内容逐项迁移。

## 6. 场景与表现迁移

32 个 `Scene/Level/Level_*.tscn` 已迁移原场景的节点、坐标、碰撞和主要视觉，去掉旧运行时脚本，由 `WorldSession` 和 `StageEncounter` 接管。

UI 必须单独审视：主菜单已搬运原场景的节点树、8 个按钮、背景、字体与装饰，脚本只接新档/继续和未迁移功能提示。背包直接迁移旧 `BackPack`、`Main_Backpack`、`Box_1`、`zb`、`equipment_properies`、`sell_or_equ` 的原节点和视觉属性，恢复原角色 Sprite2D/AnimationPlayer、翅膀和光效层、数字等级、11 像素格距以及原悬停详情和装备/出售弹窗。`Script/tests/test_inventory_scene_parity.py` 对照旧源场景验证，仅允许脚本、信号绑定和资源路径变更。运行脚本绑定新版数据；刷新只改格子数据，不重建节点。物品图标按当前可见格与装备槽加载，未预加载全部物品。其余面板状态以功能对比文档和实际场景验收为准。

`ActorView` 在玩家/怪物场景内统一挂载，读取原 SpriteFrames。`AbilityDefinition` 的 animation、cast_duration 和 release_delay 分别声明动作、持续时间、效果释放时间；Actor 负责执行，View 只显示。ActionState 的 revision 保证连续相同动作也重新播放。唐僧普攻/冰龙波的原图集、AnimationPlayer 和碰撞轨道已拆成 `Scene/Combat` 中两个独立场景，由 TimelineAttack 接到新版结算。其他角色和技能仍需逐项迁移，调试方框不能作为美术迁移完成的证据。

## 7. 内存策略与证据范围

目前已采取以下措施：

1. 关卡定义保留场景路径，进入时加载当前地图。
2. 切关卡释放旧地图、Actor 和由其拥有的飞行物。
3. 装备定义使用有界 LRU，能力定义使用弱引用缓存。
4. 物品实例不复制图标、描述和静态强化表；随机属性由 `ItemRollContext` 在实例创建时生成并随实例存档。
5. Buff 使用数值计时，避免每个实例附加 Timer 节点。
6. 波次限制同时存活敌人数，不在进入关卡时创建所有敌人。
7. 攻击来源和被动所有者使用弱引用，减少对象相互保留。

节点回收测试已经覆盖部分寿命边界，但尚未完成新旧工程在同一关卡、同一内容、相同导入/预热条件下的内存基准。不能据此承诺具体内存节省百分比，也不能把磁盘资源数量直接等同于运行内存。

## 8. 后续扩展约束

- 新输入设备实现 InputSource，不把设备判断加入 Actor。
- 新技能优先增加定义与效果组合，复杂技能增加专用效果实现。
- 新技能先在 `ContentRegistry.register_ability()` 注册，再由 `AbilityGrant` 声明来源类别；触发统一调用 `try_trigger()`。
- 新装备声明属性和能力来源，战斗规则由核心效果系统承担。
- 新地图保留合理 Scene 节点，通过定义和注入接入流程。
- UI 保存展示状态，业务状态由系统拥有；存档仅保存数据。
- 每次迁移同时记录原功能、替代接口、实际画面和测试缺口。
