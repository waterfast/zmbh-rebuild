## 商店物品描述面板定位修复
- 现象：商店悬停商品时详情面板（InventoryDetails）位置飘忽/锁死在视口顶部，与所悬停商品无关。
- 根因：重构时把背包那套「跟随鼠标 −(430,250) 偏移 + 夹到 925/590/685」的逻辑搬进了商店；老项目商店实际走 `is_in_shop` 分支（面板贴鼠标 +25,-20 并夹在 940x590 窗口内，见 oldproject Box_1.gd）。另外中途一版「悬停后单次 deferred 定位」会读到未完成布局的 ColorRect.size（场景默认 1219 高），错误触发钳制把面板压到 y=0。
- 最终方案：`InventoryItemDetails` 增加 `anchor_position`，`follow_pointer=false` 时每帧按锚点定位并钳制进视口（与 follow_pointer 对称、每帧重算，不怕布局时序）；`shop_item.gd` 用每个商品 `Shop_item.tscn` 里的 `TooltipAnchor`（Marker2D，局部 (-56,13)）作为锚点传入，商店侧钳制用 `get_visible_rect().size`。
- 回归测试：test_shop.gd 新增两条检查（悬停详情定位到锚点；面板整体保持在 940x590 视口内）。注意：切分类后 `_rows` 会重建，测试里取行前要先切回「全部」。
- 教训：SceneTree 测试脚本若中途脚本报错（如数组越界），`quit()` 不会被调用，进程会无限挂起——表现为测试"卡死"而非报错。
- 验证：test_shop 21 checks 0 failures；run_tests 43 checks 0 failures；headless editor import 无错误。

## 同问题的设计返工（用户质疑"有必要往组件里加属性吗"）
- 用户判断成立：给共享展示组件 `InventoryItemDetails` 加 `anchor_position` + 模式开关 = 把「放哪儿」塞进「画什么」，违反单一职责。
- 最终设计：组件只渲染 + 报尺寸；新增 `signal panel_resized(size)`（内容尺寸稳定后发出），定位由调用方负责。商店侧 `shop_item.gd` 连信号并在 `_place_details()` 里按 TooltipAnchor 定位、夹进视口（事件驱动，不再依赖帧时序/每帧轮询）。组件里不再有锚点相关状态；`_details` 改成 `InventoryItemDetails` 强类型，可直接访问信号。
- 遗留（本次未动，属既有设计）：`follow_pointer` / `maximum_position` / `horizontal_reposition` 仍是背包那套定位策略留在组件里，且 test_inventory_ui 用 `follow_pointer=false` 冻结面板做截图。若要彻底统一，需把跟随鼠标逻辑搬到 inventory_screen 并改测试。
- 回归测试加强：test_shop 遍历九宫 9 个格子，逐个断言「贴住所悬停商品」+「整体在视口内」，共 37 checks。
