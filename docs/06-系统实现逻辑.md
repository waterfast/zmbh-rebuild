# 各系统实现逻辑

更新时间：2026-09-21。以下路径均以 `refactor/` 为根。

## 1. 启动、装配与切关

`project.godot` 的主场景是 `Scene/UI/MainMenu.tscn`，进入游戏后加载 `app/game_app.tscn`。

`GameApp` 安装输入动作，尝试从 `user://zaomeng_profile.json` 恢复 `PlayerProfile`，随后创建 `WorldSession`、当前角色、`StageEncounter`、相机和 HUD。它负责把依赖传给系统，并连接击杀、清场、通关等信号。

切关时先解除档案对当前 Actor 的装备绑定，销毁旧 Encounter，再由 WorldSession 释放旧几何和 Actor 容器。长期数据留在 PlayerProfile，战斗对象在新关卡重建。原主菜单“读取存档”按钮打开新档/继续选择；新档存在旧进度时提示覆盖风险，继续先验证存档，再注入 GameApp，并设置 load_saved_profile=false 避免二次加载。该入口不直接覆盖存档，读取失败保留原文件。

## 2. 输入、AI、Motor 与状态

`ActorController` 接收一个 `ActorCommand`，包含 movement、jump、attack 和 ability。`PlayerInput` 调用输入源采样；`EnemyAI` 使用注入的目标，按视野与攻击距离产生相同格式的命令。

Actor 每个物理帧更新动作计时和技能冷却，消费攻击/技能意图，推进 Combatant，再根据动作状态决定是否允许 Motor 移动。Motor 设置速度、重力、跳跃和冲刺，最终调用 `move_and_slide()`；LocomotionState 根据实际地面状态与速度更新。

当前是基础横向移动、单次落地跳跃和冲刺。旧版二段跳、特殊空中动作、连招、击退和各角色专有移动规则没有全部等价迁移。

## 3. 动画与战斗表现

`ActorView.set_skin()` 按皮肤 ID 加载身体和武器 SpriteFrames，读取脚底偏移和原图朝向。`present()` 根据动作状态和移动状态选择动画，身体与武器使用同一朝向。View 不负责扣血、生成攻击或决定技能什么时候能用。

基础映射包括 `wait`、`run/walk`、`jump1`、`drop`、`hit1`、`hurt`、`death`。这证明了状态可以驱动原图集，但不能证明全部技能动画已经对齐。具体技能必须保留自身动画标识、时序和视觉资源，不能让所有 SKILL 状态都显示相同动画。

玩家和敌人场景已统一挂载 View，默认关闭调试矩形。普攻使用可选 normal_attack 定义，唐僧配置 hit1 动作长 0.55 秒、0.2 秒释放；冰龙波配置 blb 动作长 0.8 秒、0.5001 秒释放，均来自旧 Role_2.tscn 的动画事件。受击或死亡清除尚未释放的效果。ActionState.revision 使两次相同动作之间即使没有渲染 FREE 帧，也能重启动画。

TimelineAttackEffect 按需实例化 `Scene/Combat/TangSanzangNormal.tscn` 或 `IceDragonWave.tscn`，传入伤害快照和朝向。法术根节点固定在释放点，原 AnimationPlayer 同步驱动图集帧与移动的碰撞体；这类长条图集自身包含位移，不再额外叠加匀速飞行。AnimatedAttackHitbox 以原轨道事件开启新的命中窗口，同窗口对目标去重，冰龙波后续窗口可再次命中。结束时取消碰撞并释放整个场景。

旧角色根位于脚底上方 41 像素，新 Actor 根位于脚底，因此原普攻 `(±10,15)` 对应新 `(±10,-26)`，原冰龙波 `(±15,0)` 对应新 `(±15,-41)`。这些是坐标系换算，法术 Scene 内的布局不变。旧伤害随机范围、技能等级成长、击退及所有特殊状态仍未全部等价实现。

## 4. 命中与伤害

```text
Controller 命令
→ Actor/AbilityExecutor 创建攻击
→ Hitbox/Projectile 接触 Hurtbox
→ CombatResolver.resolve(HitData, target)
→ ActorHealth.damage()
→ damaged / died / damage_dealt 信号
→ 受击、被动、奖励和回收
```

`HitData` 记录威力、队伍、伤害类型、穿透、暴击、命中、硬直、Buff 和来源弱引用。`CombatResolver` 统一检查敌我、存活、无敌和闪避，然后计算防御/魔防、暴击、减伤及实际生命损失。吸血和被动使用实际伤害。霸体可以免硬直，但不自动免伤。

Hitbox 记录本次已经命中的目标，并按寿命或单目标命中销毁。取消攻击时立即阻止后续碰撞回调，再排队释放节点。普攻、技能和持续伤害共用结算入口；各角色具体普通攻击类型仍应由配置或专用攻击行为区分。

## 5. 属性、生命、Buff 与被动

`ActorStats` 计算 `max(0, (base + flat_sum) * (1 + percent_sum))`。Modifier 按唯一 source 保存，属性变更时失效缓存。装备卸下或 Buff 到期删除来源，不反向猜测数值如何恢复。

`ActorHealth` 管理当前值、上限、治疗和死亡信号。降低上限会夹紧当前生命；提高上限不会免费补血或复活。`AbilityController` 同样同步法力上限并按属性回复法力。

`BuffContainer` 保存 BuffInstance 的来源、剩余时间和周期累计量。同 ID 同来源刷新时间，不同来源可以独立存在。周期伤害先收集后结算，避免死亡回调清空 Buff 时破坏遍历。`PassiveController` 支持命中/受伤触发、概率、冷却、治疗和附加 Buff。

这是一组基础能力；原版冻结、眩晕、特殊叠层、驱散、全部状态交互和视觉表现尚未逐项映射完成。

## 6. 技能与效果

`AbilityCatalog` 先读取 ID→JSON 路径索引，resolve 时才加载定义。`ContentRegistry` 负责会话级运行时注册，法宝技能由 `RelicAbilityRegistry` 按法宝 ID 独立注册。`AbilityController` 保存 `AbilityGrant`（定义、来源 ID、类别和来源种类），移除来源不影响其他来源。移除/重新装备不会立即清空冷却，避免卸装绕过技能 CD。

角色、法宝和装备都创建 `SkillTriggerRequest` 调用同一个 `AbilityController.try_trigger()`；请求可携带类别、来源和 Actor，类别只负责筛选和 UI 区分。施法依次检查：已授予、迁移状态、冷却、法力和动作状态。全部成功后才扣蓝和开始冷却，Actor 在 release_delay 到达后调用 `AbilityExecutor` 顺序执行效果。当前提供 projectile、timeline_attack、melee、heal、self_buff、dash。技能元数据中 `metadata_only` 明确表示没有可执行迁移，不能扣蓝或进入施法动作。被打断的延迟施法取消效果，已经支付的消耗与冷却保留。

当前索引覆盖 50 个旧技能，14 个效果组合直接来自迁移内容；`CharacterAbilityRegistry` 会为每个角色把其余旧技能元数据转换为统一的运行时效果组合并注册到 `AbilityController`。`prototype` 仍不能等同于逐帧行为和全部数值对齐，技能学习、等级、完整技能树和逐技能特效仍需继续对照。

## 7. 物品、装备与经济

`ItemCatalog` 只接受合法 ID 并在定义目录内读取，默认缓存 32 个定义，也支持向会话注册单个定义。`ItemInventory.create_item_with_context()` 创建 UID，并仅在创建时通过掉落/商店/初始装备上下文掷随机属性；法宝五行也存在实例上。背包默认容量 120。

`enhance()` 修改强化等级；`socket()` 将宝石实例数据放入目标装备并从背包移除，`unsocket()` 在容量允许时取回。`EquipmentLoadout` 预留已装备物品，防止被出售或删除；装备后按来源应用属性、能力和被动，卸下后撤销同一来源。背包恢复验证 UID、随机值范围、装备定义、五行和嵌套宝石。

`ItemEconomy` 实现基础购买和出售。背包通过旧悬停详情、装备/出售弹窗、装备槽直接卸下和原分页控件访问新版数据。此前自行增加的背包强化按钮已移除：原版强化属于炼丹炉，强化业务仍可测试，但原强化窗口入口和材料规则尚未接入。高品质、强化、法宝和镶嵌装备的出售确认还未接入，出售操作暂时禁用；不以无确认出售代替旧流程。PlayerProfile 通过同一个 ContentRegistry 解析装备与法宝技能，装备卸载只撤销对应 UID 来源；尚未迁移的旧装备特效仍不会被伪造为已完成。

## 8. 世界、波次与敌人

`LevelDefinition` 保存地图路径、出生点、相机边界、下一关、门、波次和同时存活上限。`WorldSession` 加载几何 Scene 并建立 Actor 容器，打开关卡门时修改迁移场景内原碰撞形状。

`StageEncounter` 按波次中的怪物 ID 和位置生成新版 enemy，注入目标、皮肤和基础数值，监听死亡。当前数值仍按怪物 ID 推导，AI 为通用追踪/近战，不能认为旧怪物或 Boss 的专有行为已经完成。清场后开门，最后波次结束发出通关信号。

GameApp 当前发放简化击杀和通关奖励；完整掉落表、地面拾取、宝箱、NPC、机关和 Boss 多阶段机制尚未全部迁移。

## 9. 成长、任务、UI 与存档

`PlayerProgression` 保存等级、经验、金币/魂值和通关列表；`PlayerProfile` 将等级基础加成应用到 Actor。`QuestJournal` 接收击杀/通关业务事件，更新匹配任务进度并防重复领奖。当前只有两条基础任务内容，未覆盖旧版全部任务。

任务窗口 `Scene/UI/QuestJournal.tscn` 来自旧 `Scene/Task/BasicTask.tscn`，保留背景、描述区、奖励区、页签、滚动列表、领取和关闭按钮的原显示节点、坐标、字体及贴图；`QuestTitle.tscn`、`QuestReward.tscn` 和 `QuestRewardIcon.tscn` 分别复用原任务标题、奖励行及物品格。`Script/ui/quest_screen.gd` 只绑定现有任务条目，订阅 `QuestJournal.changed` 更新进度，通过 `claim()` 发放到 `PlayerProgression`，无旧 Global、AE 或每帧 UI 轮询。原日常页签可切换，当前没有已迁移的日常任务定义，显示空列表。原任务奖励为物品 ID/图标，而当前两条基础任务只有经验和魂值：保留原空物品格和奖励文字，不用文字替代图标、不伪造旧物品奖励。完整任务内容、物品奖励发放及其图标仍未迁移。`Script/tests/test_quest_ui.gd` 17/17 验证通过，包含暂停时真实点击关闭、事件刷新及防重复领奖；实际 GPU 截图为 `verification/refactor-ui/quest-journal.png`。

HUD 订阅生命、法力和成长信号，以较低频率显示技能冷却。背包和任务面板通过 PlayerProfile 访问数据。`Inventory.tscn` 直接保留旧 BackPack 根节点、背景、属性区、装备槽、Sprite2D 角色预览、原待机 AnimationPlayer 和两张等级数字 TextureRect；`InventoryGrid.tscn` 保留原 5 列 35 格、分类和分页。`InventoryDetails.tscn` 是旧 equipment_properies 的原属性层级和黑底，`InventoryActions.tscn` 是旧 sell_or_equ 原装备/出售弹窗，不再使用自行设计的固定滚动详情面板。原轮询 Timer 节点保留但停用，脚本改为订阅背包、装备、成长和属性变化并合并刷新；翻页只更新已有节点及其图标引用。

已搬运 485 张与当前定义 ID 对应的原物品图标（约 1.86 MB 源文件），运行时只按当前显示格和装备槽加载，缺失图标回退至对应槽位图。格距已经恢复原值 11，原字体、贴图、坐标、大小和动画轨道均保留。已装备物品只出现在原装备槽，不重复显示于背包物品格。属性第一页/第二页均绑定新版属性；批量出售、角色昵称持久化、翅膀/头衔显示偏好、道具/消耗品原操作窗口尚未接入。当前预览支持默认皮肤及初始唐僧装备外观，其他装备/幻化外观仍需迁移，缺失时回退默认皮肤。

`Script/ui/inventory_item_details.gd` 同时支持实例与商店定义：背包赋值 `profile` 和 `item`，展示已确定随机属性；商店仅赋值 `item_definition`，展示配置中的数值范围，不创建物品、也不调用随机掷值。店内可设置 `follow_pointer = false` 后自行控制位置，边界通过 `maximum_position` 和 `horizontal_reposition` 指定，Scene 的原布局保持不变。任务面板已绑定原场景布局，但任务内容与全部旧交互仍不完整，不能按原版全 UI 完成验收。

GameApp 与 UI 层在暂停时继续处理关闭/恢复操作，WorldSession 显式使用 PROCESS_MODE_PAUSABLE。面板打开时暂停世界并隐藏底层 HUD；关闭后按独立的手动暂停标记恢复，防止关闭背包误取消之前的暂停。B/Q 切换对应面板，Esc 优先关闭面板。所有界面都放在 CanvasLayer，避免跟随世界相机。

`SaveStore` 使用带版本与 SHA-256 校验的 JSON 信封；先写临时文件并 flush，再替换正式文件，保留备份。它保存纯数据，不序列化 Actor 节点。新版格式包括背包实例、装备 UID、成长、任务、皮肤 ID 和关卡 ID；当前不是所有旧存档的迁移器。

地图入口 `Scene/Main_menu/Map_1.tscn` 至 `Map_5.tscn` 保留原节点、背景、按钮坐标、字体、动画播放器和贴图；旧 `Map_*.gd` 的按钮目标解析到 `content/maps/routes.json`，由 `Script/ui/map_screen.gd` 接管。`MapScreen` 显式注入 `PlayerProfile` 与 `SaveStore`，按 `progression.cleared_levels` 解锁，进入关卡前显示迁移后的 `Scene/OtherScene/LevelInfo.tscn`。确认窗口继续复用原背景、敌人头像和掉落图标节点，仅将挑战信号接到新版 `GameApp`。Map_4 以后原版“敬请期待”入口保持提示，不虚构内容；Map_5 原按钮空实现同样保留不可用状态。`Script/tests/test_map_ui.gd` 23/23 和 GPU 截图 `verification/refactor-ui/map-1.png`、`map-level-info.png` 已通过。
